## 1. 现状与崩坏归因

用户反馈：`/editor/wf_087b971f1357` 开启紧凑模式后页面破版。截图取证（2026-11-05，本仓库当前未提交改动）：

- 标题被截断成「及格…」「不及…」，变量引用 chip 只剩「开… sco…」
- 输出节点标题区空白、卡片内容贴边、连线大幅绕行

### 归因（4 条，全部指向同一类问题：用 CSS 硬压完整表单）

| # | 现状代码 | 问题 |
|---|---|---|
| 1 | `styles/index.css` 中 `.gaia-editor-compact .gaia-node-form--compact *` 一把梭：`font-size:0 !important; line-height:0; margin/padding 全清零; min-height:13px` | 试图把**整个 Semi 表单 DOM**（含嵌套 Select、图标、边框、固定尺寸元素）压成胶囊。任何不可压缩元素都会以原尺寸残留 → 文字消失控件还在，正是截图症状。`!important *` 级联与 Semi/FlowGram 内部样式互相打架，无法收敛 |
| 2 | 宽度 360px → 224px | 内部表单按 360px 设计（下拉、变量 chip 最小宽度），224px 必然溢出/截断 |
| 3 | `base-node/index.tsx` 在**每个节点的 useEffect** 里直写 `renderData.update({expandable, expanded})` | 与 FlowGram 折叠态持久化机制互相覆盖；代码注释自证已因此产生两个 no-op bug（折叠裁掉端口无法连线、存量草稿缺字段 setter 短路） |
| 4 | 紧凑只是视觉压缩，节点占位尺寸/布局不变 | 卡片小了但画布间距没变，连线绕行；密度目标（一屏看更多节点）并没有真正达成 |

**结论：紧凑模式应是「渲染分支切换」，不是「样式压缩」。**

## 2. 业界对标结论

详细证据见调研报告（Coze 源码报告补充中；Dify/n8n 为 2026-11 master 源码级结论）。

| 维度 | Dify | n8n | Coze |
|---|---|---|---|
| 卡片宽度 | 全站统一 240px（`NODE_WIDTH=240`），高度随内容 | 节点 96×96 固定 + 端口数扩展（`96+32×(n-2)`）；标签**放卡片外下方** | ~242px 卡片，头部 + 变量折叠列表 |
| 紧凑形态 | 有，且与 zoom 无关：`simple-node` = 仅标题栏（图标+标题+状态图标），**同宽 240px、复用同一套 handle/状态 token**（仅 LoopEnd 用） | **没有** zoom-out 离散简化。策略：DOM 恒定 + 连续视觉补偿（zoom∈[0.2,1] 边框透明度 γ2.2 插值到 0.7）+ minimap + fitView；唯一形态切换实验在**放大**方向（zoom=max 时嵌入完整参数面板） | 无全局紧凑模式，靠缩放 + 小地图 |
| 缩小后可交互性 | `--workflow-control-scale = max(1, 1/zoom)` 反向补偿：端口命中区/悬浮工具条/+按钮屏幕尺寸恒定；分支端口例外不补偿（间距 24px 防误触） | 选中环 `6px × 补偿因子`；hover 检测节流 200ms | — |
| 运行状态 | 1px 边框换色 + 标题栏右侧 14px 图标，不占卡片空间 | 2px 边框换色 + 右下角徽标 + conic-gradient 旋转环（运行中） | 绿边/角标 |
| 业界定律 | **没有一家用 CSS 硬压做紧凑**；要么独立渲染分支（Dify simple-node），要么根本不做、靠缩放补偿（n8n） | | |

### 从对标推导的 4 条设计原则

1. **结构切换 > 样式压缩**：紧凑态是独立的渲染分支/组件，不是把完整表单压扁。
2. **紧凑 ≠ 缩放**：密度诉求交给密度档位（小卡片 + 重排），可读性诉求交给画布缩放，两个机制不混用。
3. **交互控件不随节点变小**：端口命中区 ≥16px 且缩放时屏幕恒定（Dify 反向补偿）。
4. **状态走「边框色 + 徽标」双通道**，不占卡片空间（两家共识）。

## 3. 方案规格（推荐 A：胶囊卡独立渲染分支）

### 3.1 两档密度

| | 舒适（默认，现状保留） | 紧凑（本设计） |
|---|---|---|
| 卡片 | 360px 白卡，头部+描述+完整表单+端口行，高度自适应 | **260×36 单行胶囊**（多端口节点加高，见 3.3） |
| 内容 | 现状 | 分类色图标芯片(20px) + 标题(13px/500, ellipsis) + 右侧状态徽标 |
| 端口 | 行内端口（现状） | 边缘圆点（见 3.3） |
| 状态 | NodeStatusBar | 边框换色 + 7px 徽标点（复用 `statusDotColor` 色值口径） |
| 触发 | 偏好 `gaia.editor.prefs.compact`（localStorage，已存在） | 同左；工具栏/偏好面板入口 |

宽度取 260 的依据：标题可读（截图证明 224 不够）；Dify simple-node 同宽 240 经验；260 与舒适态宽度接近，切换时节点横向错位小。

### 3.2 紧凑卡解剖

```
│◄────────────────── 260 ──────────────────►│
 ──┤ [▤] 生成点评 ······        ● ├──
●─┤ (芯片20) (标题13 ellipsis)  (徽标7) ├─●
```

- 圆角 10px、边框 1px `--ge-border`、阴影 `--ge-shadow-sm`（token 复用，双主题自动适配）
- 状态：默认无；选中 accent 边框 + 3px 光环；运行中蓝边+呼吸点；成功绿；失败红；校验错误保留左上 ErrorIcon
- 隐藏项：描述、副标题、表单、端口行、`···`菜单（右键菜单保留）、端口 `+` 创建按钮（紧凑态下加节点走左侧面板/右键）

### 3.3 端口（连线能力完整保留）

- 输入端口 = 左缘圆点(6px)，输出 = 右缘圆点；命中区 16px
- 多端口加高阶梯：1 端口 36px；2 端口 48px（y=15/33）；3 端口 64px——纵向间距 ≥16px（Dify 分支端口 24px 间距教训的折中，命中区相切不重叠）
- 悬停端口显示 11px 端口名标签（`if` / `else` / `score`…）
- 实现上沿用 FlowGram 原生折叠态渲染端口（`getNodeMeta().defaultExpanded` 注册折叠，而非 useEffect 直写 `renderData`），连线、拖线建节点（保留开关时）均可用

### 3.4 交互

| 手势 | 行为 |
|---|---|
| 单击 | 选中（与现状一致，框选/多选不变） |
| **双击** | **临时展开该节点**（仅此节点恢复完整卡，再次双击收回；全局偏好不变）——大流程中快速查看/修改单个节点的主路径 |
| 悬停 500ms | tooltip：类型 · 标题 + 副标题摘要（Coze/n8n 均 500ms 延迟口径） |
| 右键 | 菜单不变（重命名/副本/试运行此节点…） |
| 拖端口 | 连线不变 |

### 3.5 布局联动（让密度真正提升）

- 切换密度档位 → 用对应尺寸表触发一次自动布局（后端 ELK 真实尺寸分层已支持，commit 20b544fb）
- 紧凑尺寸表：胶囊 260×36/48/64 + 层间距收紧；舒适尺寸表现状
- 效果口径：单节点占地 360×~150 → 260×36，单位面积节点数 ≈5×
- 采纳 Dify `--workflow-control-scale`（P2）：zoom<1 时端口命中区/小地图/悬浮工具屏幕恒定
