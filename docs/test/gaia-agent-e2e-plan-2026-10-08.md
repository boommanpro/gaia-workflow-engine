# Gaia Agent E2E 测试计划（20 用例 · 自研 local 引擎 · 2026-10-08）

- 被测对象：gaia console（localhost:3001）+ gaia-workflow-app（localhost:48080）
- 执行引擎：local（自研编排，`agent.engine.default={"mode":"local"}`）
- LLM：局域网 Qwen3.6-35B（`http://192.168.1.11:8082/v1`，正式配置）
- 测试方式：浏览器 GUI 黑盒模拟真实用户（点击/输入/截图验证），发现 bug → 修复 → 重试
- 干净基线：清空 agent_session / agent_message / agent_artifact / agent_permission 后重启后端；
  保留 agent_config、agent_tool_definition 与既有 8 个工作流（作为查询类用例的数据基础，其 id 已记录可对比）

## 会话模型前提（断言依据）

1. 会话 = 草稿空间：AI 变更先落在会话草稿，不直接改线上工作流
2. `applyWorkflow` 走确认门禁（require 模式）：对话流中出现「应用 & 保存版本」卡片，确认后才落为生效版本
3. 一次用户消息 = 一条流式回复，多次工具调用 merge 在同一回复内
4. 右栏版本切换器两轴：本会话版本（游标）+ 落版版本（查看）
5. 确认挂起超过 300s 自动拒绝

## 执行纪律

- 每个用例新起会话（或在指定用例的会话内续跑）；用例间不共享上下文（除注明「接 TCxx」）
- 确认卡片出现后 60s 内点击，避免 300s 超时自动拒绝干扰断言
- 每个用例记录：实际回复摘要、工具调用序列（Debug 面板/DB）、截图、PASS/FAIL、缺陷单
- 发现 bug：先最小复现 → 定位（前端/工具/后端）→ 修复 → 重编译重启 → 重跑该用例
- Qwen 较慢（开思考模式），单轮等待上限放宽到 5 分钟，超时视为 FAIL 并查后端日志
