阅读说明

以当前工作区 src/main/resources/sql/schema.sql 为结构依据，以实体和删除入口核对业务行为。没有读取生产数据库，也不把 target 或 extracted 构建副本当成源文件。实际存量库可能存在迁移差异。

SQLite 数据源与每次启动执行的初始化策略见配置。[56]类型栏保留 DDL 声明：VARCHAR 长度不构成 SQLite 强制长度校验；TINYINT 不是布尔约束；未声明 NOT NULL 的字段允许 NULL（INTEGER PRIMARY KEY 仍具有主键语义）。默认值不等于非空限制；JSON 存于 TEXT，DDL 没有 JSON 格式校验。枚举说明属于业务约定，不是 CHECK 约束。

所有示例均为合成数据，不是数据库导出，也不是可直接调用的 API 请求。TEXT 中的 JSON 保留为转义字符串；示例画布仅展示存储形状，不承诺可执行。密钥使用虚构值。无外部网络依赖，复制时请保留同目录资源。

结构校验：程序解析 DDL 后在内存 SQLite 中建表，读取 PRAGMA 元数据；逐字段生成并验证完整样例插入。schema SHA-256：f95edbfb655d1adaa0b9e3d80ad26f7f89cac2c627b2ad89e4217ce35ff083dc。

删除与留存

13 张表带有逻辑删除标记；其余 9 张表没有该字段。MyBatis-Plus 的逻辑删除配置为 0 未删、1 已删；直接 SQL DELETE 仍会物理删除，不受 ORM 语义保护。[56]

schema 没有 FOREIGN KEY、ON DELETE CASCADE 或触发器。删除主记录不等于相关记录被清理；下方逐表说明区分实体能力与具体入口行为。软删不会释放 UNIQUE 键，旧记录仍占用业务编码；历史表的普通索引也不等价于唯一版本约束。

启动脚本明确 DROP 已下线的六张历史表：agent_graph_node、agent_graph_edge、agent_permission、agent_global_permission、agent_knowledge_chunk、agent_memory。这是物理清表，不属于当前 22 表。[57]
