# 规范变更流程

不改变既定原则的修复直接按领域检查单实施。新增能力、改变规范、破坏兼容或迁移权威资源位置时，在此目录新增 `<日期>-<主题>/`：

```text
proposal.md
design.md
tasks.md
```

- proposal.md：状态（待批准/已批准/已完成）、问题、范围、非目标、影响的规则编号、拟议规范差异、批准依据。
- design.md：接口、数据流、兼容与迁移、安全、失败处理和回滚；简单变更可在提案中记录设计并说明省略理由。
- tasks.md：可验证任务、验收命令、结果和未完成项；不得提前勾选。

提案批准前不得把拟议规则写成已生效规范。实施完成后更新相应 spec.md、checklist.md、status.md，再将变更目录移至 archive/；未全部完成不得归档为完成。archive 按首次实际归档时创建，不预置空目录。

已批准的节点契约重构以现有设计及 status.md 为基线，不需要重复申请相同范围。新的执行语义细节若改变已批准原则，仍需单独说明并确认。

此流程借鉴 OpenSpec 的变更分离，但不使用其 CLI 增量语法；不要对本目录运行工具并假定自动兼容。
