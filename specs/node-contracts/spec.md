# 节点契约规范

状态：已批准。范围：节点定义、画布适配、后端校验执行、AI 契约查询和工作流发布。

“必须/不得”是开发约束；“目标约束”是已批准但尚未全量实现的方向。目标约束仅在实施对应能力时作为验收标准，不授权无测试地一次性改变所有旧行为。当前实现见 [status.md](status.md)。

## NC-01 权威资源与能力分类（立即适用）

以下路径相对于仓库根目录。资源根 R 为 `apps/api/gaia-workflow/gaia-workflow-app/src/main/resources`。

| 事实 | 唯一维护位置 |
|---|---|
| 节点身份、能力、目录版本、Schema 路径 | R/node-catalog/index.json |
| 节点默认 data | R/node-catalog/defaults.json |
| 字段类型、包装、枚举、必填约束 | R/node-schemas/*.schema.json |
| 特殊 UI 及画布生命周期 | apps/console/src/nodes |
| 执行算法 | 后端节点解析器与执行器 |

可执行、可由 AI 创建、容器、内部节点是不同能力。不得强求画布注册、AI 清单和执行器数量相同。可生成类型必须由目录能力派生，不另写名单。新增展示类型若尚不在机器目录中，须显式标注能力，不给它虚构执行器。

场景：新增可生成类型后，前后端清单必须同时反映能力声明；仅内部节点不得因为有 Schema 就暴露为顶层 AI 创建类型。

## NC-02 单一 Schema 与加载失败（立即适用）

复用现有 Draft-07；公共引用使用该草案支持的 definitions 与本地 $ref。未经兼容验证不得混用其他草案关键字。扩展键必须有消费方和测试，不能把元数据视为已执行的约束。

已登记契约缺失、损坏或无法编译必须阻止服务按正常状态启动。调用者必须先验证类型，不能把未知类型的空校验结果当作合法。前端自制 Schema 子集校验器不是完整标准校验器，测试结论必须保留这一边界。

场景：已登记的 http Schema 丢失时启动失败；目录外类型不能经“无错误”绕过运行入口。

## NC-03 默认值、复制与创建（立即适用）

新接入和修改中的 onAdd 必须复用共享默认值，不另写相同业务数据。ID、布局、展示标题等实例行为可以由画布负责。默认值只能作为编辑起点，不表示可执行；不得填入真实凭证或虚假业务地址来通过校验。

取默认值必须深拷贝。数组更新默认整体替换，不按索引隐式合并。未知类型明确失败，不回退成 variable 或其他类型。规范节点创建不隐式猜测 AI 简写；显式转换器必须可追踪、幂等且不修改输入对象。

场景：创建两个 HTTP 节点，修改一个请求体不影响另一个和目录；两项条件更新为一项后不得残留第二项；规范 body/timeout 重复转换结果不变。

## NC-04 前端与 AI 消费（立即适用）

前端读取契约来源，不复制字段规则。复杂代码、条件、循环、提示词控件可保留专用实现，但必须写入规范字段路径。AI 查询应在知识散文缺失时仍返回有效契约；禁止通过新增提示词字段表补偿机器定义缺失。

场景：节点说明文档缺失但 Schema 存在时，AI 仍能得到参数约束和默认值；字段约束变化不要求手改多份参数散文。

## NC-05 草稿与执行门禁（目标约束）

草稿、试跑、测试、任务执行与发布应复用同一分层校验链：结构 → 字段 → 节点语义 → 递归图和作用域 → 资源与权限。阶段差异必须是显式策略，不是各入口自行裁剪规则。

草稿仅允许显式白名单中的不完整状态，例如缺业务输入、未连通、未选择凭证。未知字段、错类型、缺值包装判别字段、重复 ID、悬空引用、非法容器、已确定的类型不兼容不得软放行。没有完整实现该策略前，不应直接把旧校验错误全部降成警告。

场景：缺地址可保存待配置草稿，但不能运行；错误包装对象不能因为第一次出现而进入有效草稿。

## NC-06 图、端口与绑定（目标约束）

顶层唯一 start 是入口，顶层唯一 end 定义结果（2026-10-26 起立即适用：`MULTI_START` / `MULTI_END` 均为 error，条件/分支的各路径汇合到同一个 end；见 changes/archive/2026-10-26-end-node-uniqueness）；孤立执行节点不能因零入度自动运行。循环只能通过容器表达，必须递归校验内部节点。边身份包括起终节点和起终端口。

变量选择器、AI 与运行器应使用同一作用域语义；引用支持明确的深层路径，区分缺失与 null，保留数字、布尔、对象类型。上游可达不等于分支必达；不能证明可用的输出必须拒绝或要求显式默认策略。输出声明还须验证真实执行结果。

场景：同起终点不同端口的两条边不去重；循环局部变量不泄漏；三段引用不得静默返回第二段对象；孤立副作用节点不能执行。

## NC-07 AI 闭环与错误协议（目标约束）

采用查询契约、修改草稿、确定性校验、有限修复、测试反馈的流程。错误至少可定位到错误码、节点、字段路径和文档修订。默认修复预算三轮，同错误连续两轮无进展停止并解释。

不猜凭证、地址、字段或业务条件。模型结构化输出不替代后端校验。测试证据绑定草稿语义摘要、执行依赖、输入和断言版本；业务修改后旧证据不得标为当前候选通过。

场景：第十版测试通过后，第十一版修改条件，必须显示待重测而非继承成功。

## NC-08 版本、发布与迁移（目标约束）

文档格式版本、节点版本、草稿 revision、发布 releaseId 不得混用。历史执行需锁定契约、解析器、执行器及公共绑定语义产物；未知版本不得回退 latest。

发布必须冻结候选，编译内容与入库内容相同；提交同时检查草稿修订和读取时正式基准。正式版本不可原地改正文。子流程锁定实际版本，不依赖执行时当前版本。

迁移生成新发布身份，保留 sourceReleaseId 和摘要，依赖闭包一起验证后切换。回滚恢复旧指针，不改历史记录。清库必须另行确认。

场景：编译期间草稿变化时发布返回冲突；缺历史执行产物时明确拒绝，不用新实现冒充旧版本。

## NC-09 知识同步与安全（立即约束新增代码，完整同步机制待实施）

生成契约知识与人工策略覆盖分层；生成内容不允许作为独立可编辑字段规则。更新人工内容须保留来源、批准版本和冲突差异，不能静默覆盖。日志与示例不得携带密钥；凭证使用引用，执行时按权限解析。

场景：源提示词与数据库人工版本均变化时，不覆盖任一方并伪称已同步；有副作用测试未经授权不得访问真实业务目标。

## NC-10 变更验收（立即适用）

每次变更须按 [检查单](checklist.md) 运行受影响测试，并说明失败及未执行项。定义、默认值、前后端消费、知识查询与实际输出之间的一致性必须有测试。通过 Schema 不等于业务通过；目录中 version 存在不等于版本锁定完成。
